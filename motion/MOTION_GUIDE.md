# 모션그래픽 영상 제작 가이드 (Claude Code용)

> 이 문서는 **Claude가 읽는 작업 지침**이다. 사용자(한의사, 코딩 비전문가)가 새 영상을 요청하며 이 파일을 첨부하면, 아래 파이프라인·디자인 규칙·QA를 그대로 따른다.
> 기준작: 봉침 트로트 뮤직비디오 v3.1 (`videos/ilo_bongchim_reel_v3_1.mp4`), 코드 `motion/template/`.

## 0. 사용자와 결과물
- 사용자: 일로한방병원 원장. 코딩 모름. 설명은 쉬운 한국어, 전문용어 없이.
- 용도: 원내 대기실 TV. **16:9, 1920×1080, 30fps**. 의료광고 심의 기준은 적용하지 않음(원내용).
- 합성 도구: Remotion·HyperFrames 쓰지 말 것. **HTML + 헤드리스 Chromium 프레임 렌더 + ffmpeg**(Claude Code 기본 기능).
- 음성: 기본 Gemini TTS(Puck 목소리, 대본 전체를 한 번에 녹음해야 목소리가 일정함). ElevenLabs는 요청 시에만(Klamon). 노래는 ElevenLabs 음악(`ElevenLabs_Full` 커넥터, `estimate_only` 먼저, 생성 재시도 금지).
- API 키는 채팅으로 받지 않는다(환경 시크릿/프록시 주입). `.env`의 `GOOGLE_API_KEY`는 placeholder.
- 숫자 읽기: "1제"는 TTS 대본에 "한 제", 날짜는 "시월 삼십일일"처럼 풀어 쓴다(화면 표기는 1제 그대로).

## 1. 렌더 파이프라인
1. 페이지 한 장(`*.html`)이 `window.render(t)`를 노출한다. **같은 t → 항상 같은 화면**(결정적). `Math.random` 금지, `hash(n)` 사용.
2. `window.fitAll()`(async): 모든 장면을 한 번씩 렌더해 등장 글자를 모은 뒤 글꼴 서브셋을 미리 로드. 안 하면 일부 프레임이 대체 글꼴로 찍힘.
3. 렌더: `motion/template/split.sh` → 4 워커 병렬, **60fps**로 PNG 저장 (82초 기준 약 12분).
   - `NODE_PATH=$(npm root -g)`, Playwright Chromium은 `/opt/pw-browsers`. `playwright install` 금지.
4. 인코딩 (60fps → 두 장씩 섞어 모션 블러 → 30fps):
   ```bash
   ffmpeg -framerate 60 -i frames/f_%05d.png -i song.wav \
     -vf "tmix=frames=2:weights='1 1',fps=30,format=yuv420p" \
     -c:v libx264 -preset slow -crf 20 -g 60 -keyint_min 60 -sc_threshold 0 \
     -c:a aac -b:a 192k -shortest -movflags +faststart out/final.mp4
   ```
5. 전달: 채팅 첨부는 **30MB 제한** → 2-pass `-b:v 2600k -g 60`(82초≈28MB) 사본을 SendUserFile. 원본은 저장소 `videos/`에 커밋·푸시하고 GitHub 링크 제공.
6. 미리보기: `node render.js page.html st 30 0 1.0,8.2,23.3,...` (정지 화면) → `python3 motion/tools/contact_sheet.py st` → 3×3 시트를 Read로 확인. **전체 렌더 전에 반드시** 40장 내외로 점검.
7. 글꼴: npm fontsource 패키지에서 woff2를 받아 로컬 경로로(jsdelivr 차단). 현재 사용: Black Han Sans(제목), Pretendard 700/800/900(본문).

## 2. 디자인 규칙 — "테마 하나"
v2가 산만했던 이유: 레퍼런스마다 색·글꼴·장식(HUD, 손글씨 주석, UI 카드)을 따로 가져와 색 6개·글꼴 5개가 섞임. **반드시 지킬 것:**
- 작업 시작 시 **테마 한 문장**을 정한다(예: 봉침 = "꿀 한 방울": 꿀색, 벌집, 떨어지는 움직임). 사용자에게 먼저 보여주고 진행.
- **배경색 3개 + 강조색 1개**, **글꼴 2개**. 강조색은 의미 있는 단어에만(봉침 v3: 통증 단어만 주황).
- 레퍼런스 기법은 **구조만 빌리고 모양은 테마로 바꾼다**. 예: 로딩 링 → 꿀이 차오르는 육각형 칸, 점 격자 → 벌집 무늬, 터널 → 천천히 다가오는 벌집 줌.
- 같은 모티프를 장면 사이에 반복(꿀방울이 인트로→그래프→엔딩까지). 후렴은 두 번 다 같은 디자인(반복이 곧 통일감).
- 한 단계 더: 주인공 오브젝트 하나가 모양을 바꿔가며 장면을 끌고 가는 "한 컷 연속 변신"(7-5, ㉑), 공 하나가 주인공인 구성(⑯), 글자·도형만으로 확대·축소하며 공간을 넓혀가는 구성(7-6, ㉒). 사용자가 좋아하는 방식이니 새 영상 기획 때 먼저 제안한다.
- 테마와 무관한 장식 금지: 타임코드·프레임 카운터 HUD, "squash!" 같은 제작 용어 주석, 앱 UI(커서·토스트·슬라이더)는 테마가 그것일 때만.
- 글자 색은 배경 모드에 따라 자동 전환(`.ad` 클래스 + `adapt()`), 전환 도중에도 읽히게.
- 화면 아래 가사/자막 캡션(둥근 알약, 부르는 단어까지 강조색 채움)은 하단 ~130px를 차지 → 다른 요소는 y≈930 위에.

## 3. 움직임 문법 (부드러움의 핵심)
v2 측정: 완전 정지 구간 50곳(31초), 급정지 26곳 → 사용자 체감 "멈칫멈칫". v3에서 0/0으로 해결한 방법:

| 규칙 | 구현 (template 참고) |
|---|---|
| 모든 요소 등장 = 스프링 착지 | `spring(p) = 1 - exp(-6.5p)·cos(8.5p)`, 기본 0.55초, ~8% 한 번 넘쳤다 안착. 낙하 중 세로로 늘어나고 착지 때 살짝 눌림(속도 기반 stretch) |
| 자리 잡은 뒤에도 정지 금지 | `A()` 안에서 float(±4~5px 사인)와 5초간 3.5% 확대 |
| 퇴장도 움직임 | 같은 방향으로 계속 내려가며 녹아내림(0.24~0.32초, fade+blur). 다음 요소 등장과 **0.2~0.3초 겹침** |
| 방향 통일 | 봉침 v3는 전부 위→아래(꿀이 흐르는 방향). 테마마다 하나로 정함 |
| 배경 항상 움직임 | 벌집 무늬 이동(16,9 px/s) + 빛번짐 2개 표류 + 박자마다 몇 칸 반짝 + 강조 순간 물결 |
| 카메라 숨쉬기 | `#cam` 전체를 ±10px 표류, 1.02±0.012 배율. 강조 순간은 부드러운 bump(0.07초 상승, 지수 감쇠) — **랜덤 흔들림·흰색 플래시 금지** |
| 장면 사이 겹침 | 섹션 경계 후 0.5초 동안 이전 섹션도 계속 렌더(퇴장 애니메이션 완료). 섹션마다 별도 컨테이너, id 조회는 `Q(id)`로 섹션 범위 안에서만 |
| 배경 전환 = 원 퍼짐 | 한 점에서 물결진 원이 퍼지며 새 배경(0.3~0.55초). 하드 컷 금지 |

핵심 헬퍼 시그니처 (`motion/template/mv_template.html`):
```js
A(id, t, t0, t1, {dy, dx, sc, dur, out, jelly, float, hit, extra})  // 등장(t0)·유지·퇴장(t1) 한 번에
BGT = [[time, mode, x, y, dur, fast?], ...]   // 배경 전환 타임라인 (mode: dark|cream|honey)
RIPS = [[time, x, y, strength], ...]          // 벌집 물결 시점
sbeat(t)  // 부드러운 박자 펄스(0→1→감쇠), pulse()보다 이것을 쓴다
```

## 4. 박자 맞추기
- 박자: `motion/tools/beats.py song.wav beats.js`(librosa). 가사 단어 시각: ElevenLabs Scribe(`creative_transcribe_audio`) 단어 타임스탬프 → `LINES` 배열.
- **강조 단어(후렴 큰 글자, "딱!", "쏙!")는 박자 0.1초 전에 출발**하고 `hit:1` 옵션(0.4초, 불투명도·블러가 거의 즉시 완료) → 박자 순간에 이미 또렷.
  - 일반 등장(불투명도가 천천히 올라감)을 박자에 쓰면 사용자가 "살짝 늦게 나온다"고 느낌(v3 → v3.1 수정 사항).
- 강조 순간의 배경 전환은 **박자 0.13초 전 시작, 0.26초, ease-out**(`BGT`의 6번째 값 1) → 박자 순간 88% 완료. ease-in-out이면 2%뿐이라 늦어 보임.

## 5. 금지·주의 (눈 피로)
- 원내 TV는 환자가 오래 본다. **1초에 3회 넘는 큰 밝기 변화 금지.**
- v2 39~41초: 색이 다른 큰 사각형이 빠르게 회전하는 터널 → 초당 12~21회 깜빡임 → "번쩍여서 눈이 아픔". 터널/스트로브/흰 플래시 금지.
- 빠르게 흐르는 고대비 글자 줄은 초당 ~900px 이하, 투명도 낮게(0.1~0.26).
- 단어 교체 겹침이 0.3초를 넘으면 글자가 지저분하게 겹쳐 보인다.

## 6. QA 체크리스트 (보내기 전 필수)
1. 정지 화면 시트로 겹침·대비·잘림·자막과의 충돌 확인.
2. `python3 motion/tools/check_motion.py out/final.mp4`
   - static holds 0, abrupt stops 0 목표.
   - flicker: 원 퍼짐 전환 1회는 2~4로 잡힐 수 있음(정상). **연속 초에 10+면 스트로브 → 반드시 수정.**
3. 강조 단어는 박자 시각 정지 화면에서 또렷하고 배경이 거의 바뀌어 있는지 확인.
4. 길이·오디오 싱크(`ffprobe` duration), 30MB 사본 크기.

## 7. 기법 카탈로그 1차 (레퍼런스 ①~⑦에서 추출)
출처: ①Opus 5.5 홍보(정사각) ②TanStack ③Claude 릴(가로) ⑤Claude 릴(세로) ⑥애니메이션 원리 ⑦develop. (④ 없음)

**글자**
- 뜻대로 움직이는 단어(①⑥): 시큰=찌그러졌다 튐, 계단=글자가 계단식, 멈칫=떨다 정지, 뻐근=가로로 늘어났다 복귀, 올라가=떠오르다 떨어짐, 찌릿=지그재그 떨림+기울임, 뻣뻣=로봇처럼 끊긴 회전, 푹=주저앉으며 납작, 참지 마요=가로줄 긋기.
- 고정 라벨 + 바뀌는 단어(①): 좌상단 "이럴 때 · 무릎" 고정, 가운데 단어만 교체.
- 단어별 끊어 등장(①), 마침표 색 점(①), 글자 고리 LOOP(① — 타원을 따라 글자 회전, 앞뒤 깊이감), 흐르는 단어 줄(⑤), 자간 좁히기(②③ — 병원 이름), 타이핑+깜빡이는 커서(⑦), 말풍선/알약이 가로로 자라기(⑦).

**도형·그래픽**
- 처리 과정 노드 + 점선 + 입자 정렬(②⑤): 필터 지점 전엔 흩어진 입자, 후엔 가지런한 강조색 입자.
- 궤도 타원(②): 이름 둘레 점선 타원 위를 작은 모티프가 돎.
- 곡선 그래프(③⑥): 선이 그려지며 모티프가 곡선을 타고 내려감(통증 감소).
- 퍼센트 로딩 → ✓(⑥⑦): 테마 도형 안에 차오름, 100%에서 ✓.
- 광택 구체(①⑤), 모양 변신 격자(⑤), 점 격자 물결(③), 점 구(③), 따라오는 점 꼬리로 그리는 하트(⑥).

**전환**
- 원 퍼짐(⑦) ← 기본값으로 쓸 것. 박자 색 전환(①)은 원 퍼짐으로 부드럽게. 큰 도형이 다음 장면 배경이 되기(⑦).

**움직임 원리(⑥)**: 스쿼시·스트레치, 예비동작(로딩·두근두근으로 후렴 직전 긴장), 천천히 시작/멈춤(linear 금지), 오버슈트, 팔로스루, 포물선 바운스(박자마다 튀는 공, 높이 0.88배씩 감소).

## 7-2. 기법 카탈로그 2차 (레퍼런스 ⑧~⑫)
⑧~⑫는 다섯 편 모두 **테마가 처음부터 끝까지 하나**다. 기법보다 이 "디자인 체계"를 먼저 본보기로 삼는다.

| # | 파일 | 영상 | 디자인 체계 (배경 / 강조 / 글꼴) | 구조 |
|---|---|---|---|---|
| ⑧ | original_8 (58s) | Claude 기능 소개 | 짙은 갈색-검정 + 중앙 따뜻한 비네트 / 코랄 1색 / 세리프 제목 + 이탤릭 세리프 부제 + 작은 모노 라벨 | 타이핑 오프닝 → 워드마크 → `01 — REASONING`식 챕터 9개(같은 레이아웃 반복) → 가치 3줄 → 타이핑 엔딩 |
| ⑨ | original_9 (30s) | IdeaVim | 밝은 회색 / 청록 블록 커서 1색 / 모노 + 산세리프 | 한 문장 타이핑 → 실제 코드 편집 시연 → 기능 카드 → 로고 |

**글자**
- 타이핑 오프닝·엔딩(⑧⑨⑩): 커서가 깜빡이며 한 글자씩. 끝난 문장은 **블러로 흐려지며 빠짐**(⑧ "anything"), 또는 작게 줄어 위로 올라가 다음 문장의 머리말이 됨(⑨).
- 쌓이는 목록(⑪): 새 줄이 아래에 생기면 이전 줄은 회색으로 흐려지고, 현재 줄 앞에만 강조색 점. 한 글자씩 부드럽게 페이드.
- 단어 단위 블러 등장(⑧⑪): 제목이 단어마다 흐림→선명 + 살짝 위로. 키워드 한두 단어만 강조색.
- 극단 클로즈업 → 빠지기(⑪): 단어 일부("red")가 화면을 꽉 채운 채 옆으로 빠르게 지나가다 줌아웃되어 전체 단어("hired.")가 드러남. 강조 순간에만 1번.
- 흩어진 단어가 문장으로 모임(⑪): 단어들이 제각각 위치·기울기로 떠 있다가 제자리로 모여 한 줄이 되고 밑줄이 그어짐.
- 단어 교체 + 밑줄 길이 따라감(⑧): "Claude can ___." 고정, 마지막 단어만 바뀌고 밑줄이 새 단어 길이로 늘었다 줄었다 + 아래 진행 점(●●○○).
- 세로 회전 목록(⑪): 단어가 아래에서 올라와 가운데서 진하게, 위로 가며 흐려짐(룰렛). 언어 카드 넘기기(⑧ Hello→Bonjour→こんにちは)도 같은 계열.
- 세로선이 자라며 줄이 쌓임(⑧): "Helpful. / Honest. / Harmless." 왼쪽 강조색 세로선이 줄 수만큼 길어짐. 마침표만 강조색.
- 하이라이트 박스(⑩): 마지막 단어("again.") 뒤에 강조색 사각형이 왼→오로 칠해짐.
- RGB 분리 글리치(⑫): 질문 문장("system?")에 색 번짐과 흔들림. **원내 영상엔 약하게, 1번만.**
- 아주 굵은 와이드 이탤릭 + 기울어진 3D 패널(⑫): 강한 메시지 장면용.

**도형·그래픽·UI**
- 챕터 반복 레이아웃(⑧): 좌측 "번호 — 분류 / 제목 / 이탤릭 설명", 우측 시연 카드. 장마다 좌우를 바꿔 지루함 방지. 하단에 전체 진행 막대.
- 시연 카드(⑧⑨⑩): 실제 동작을 짧게 재현. 질문→세 갈래 나무→결론 버튼(⑧), 초안 타이핑 + 단어 줄긋고 고치기(⑧), 체크리스트가 하나씩 ✓(⑧), 코드 편집 + 모드 표시 + 누른 키 캡(⑨), 같은 단어 여러 곳 동시 수정(⑨).

**주인공 캐릭터·오브젝트 (테마 통일의 가장 강한 방법)**
- 공 하나가 처음부터 끝까지(⑯): 잔상 점선을 남기며 튀고, 문서 카드들을 빨아들이며 불꽃이 튀고, 그래프 선을 따라 달리고, 마지막에 로고의 점으로 착지. **봉침 v3의 꿀방울과 같은 원리**. 다음 영상에서도 테마 오브젝트 하나를 정해 이렇게 끝까지 끌고 간다.

- 마스코트(⑬): 위에서 스포트라이트, 눈 깜빡임, 말풍선이 타이핑, 마지막에 눈이 별로 바뀜. 병원 캐릭터가 있으면 그대로 응용.

**글자**

- 문장을 이어 쓰기(⑰): "Meet → Meet your → Meet your new associate." 같은 자리에서 단어가 붙어 나감.
- 질문 틀 + 마지막 단어 교체 + 이모지(⑮): "ONDE FICA O BRUNCH? / CAFÉ? / SUSHI?" 뒤에 거대한 "?" 워터마크. 모션 블러로 단어가 휙 바뀜. **"어디가 아프세요? 무릎? 어깨? 허리?"에 바로 응용 가능.**
- 글자가 와르르 떨어져 쌓임(⑯): 큰 헤드라인 글자가 위에서 하나씩 굴러떨어져 자리 잡고, 나중엔 글자들이 무너져 그래프 축이 됨. 글자에 색 그림자(입체 오프셋).

## 7-5. 한 컷 연속 변신 (레퍼런스 ㉑ — 사용자가 특히 좋아한 기법)
㉑ original_21 (32s, DistilBook "문서를 영상으로"): **컷이 하나도 없다.** 한 장면의 마지막 모양이 다음 장면의 첫 모양이 되고, 카메라는 처음부터 끝까지 화면 가운데로 계속 전진한다. 마지막엔 같은 길을 거꾸로 빠져나와 첫 장면으로 돌아온다.

**실제 연결 사슬 (모양 → 모양)**
1. 종이 위 문서(손그림, 옆에 붉은 별꽃 캐릭터) — 마지막 줄 끝의 **점**에 원이 그려지며 카메라가 다가감
2. 점 → 들여다보는 **구멍** → 안쪽에 우주(별 하나 + 궤도 + 색 막대들 = 문서 속 생각들)
3. 가운데 **별**로 돌진 → 화면이 하얗게 → 그 흰색이 **종이 한 장**이 되어 줄어들며 회전 → 가는 **빛줄기**
4. 빛줄기가 **프리즘**을 통과 → **무지개**(= "정제(distill)"의 은유, 로고의 색 막대와 같은 색)
5. 무지개가 화면을 채움 → 각 색 띠가 **필름 띠**가 되고 칸마다 결과물 카드
6. 필름 띠들이 꼬여 **나선** → 그 속으로 들어가는 **터널**
7. 카드들이 색 **입자**로 흩어짐 → 새 떼처럼 **군무** → **음파 모양**으로 정렬
8. 음파가 납작해져 **한 줄** → 줄이 말려 **원** → 반짝이 아이콘 → 원이 **무지개 고리**로 번지며 그 속으로 돌진
9. 우주에서 **연필**이 솟아 선을 그음 → 선이 휘어 **행성 지평선**(책 표면) → 그 위에 결과물 카드 한 장 → 카드 확대
10. 줌아웃: 카드가 수백 장 **격자** → 격자가 말려 **공** → 공이 **별** → 다시 우주 → 구멍 → 점 → 처음의 종이 문서(카드 한 장이 결과로 바뀜) → 로고

**원리 (따라 만들 때 지킬 것)**
- **모양 이어받기(매치 컷)**: 장면 N의 끝 모양과 크기·위치·색이 장면 N+1의 시작 모양과 정확히 겹치는 순간에 바꾼다. 점=구멍, 별=흰 화면, 흰 화면=종이, 종이=빛줄기, 무지개 띠=필름 띠, 카드=입자, 입자 줄=선, 선=원, 카드 격자=공=별.
- **한 방향 카메라**: 대부분 "화면 가운데로 전진(줌인)". 방향이 바뀌는 건 마지막 귀환(줌아웃) 한 번뿐이다. 그래서 흐름이 끊기지 않는다.
- **가운데 고정점**: 변신은 거의 항상 화면 중앙에서 일어난다. 시선이 한 점에 머물러 따라가기 쉽다.
- **색 실 하나**: 무지개 6색(= 로고 색)이 우주의 막대, 무지개, 필름 띠, 입자, 고리에 계속 등장한다.
- **수미상관**: 시작 장면(종이·문서·별꽃 캐릭터)으로 돌아와 끝난다. 처음엔 문서였던 자리에 결과물이 놓여 있다 = 이야기의 변화가 한 프레임에 보인다.
- **각 변신이 곧 메시지**: 프리즘 = 정제, 필름 띠 = 영상, 연필 = 그림 생성. 장식이 아니라 제품이 하는 일을 비유로 보여준다.
- 배경은 손그림 종이 ↔ 짙은 남색 우주 두 세계만 오간다.

**우리 파이프라인에서 구현하는 법**
- 포털 줌: 목표점 (x, y)을 기준으로 `scale = exp(k·t)`처럼 지수로 키운다(선형이면 끝에서 느려 보임). 다음 장면은 `1/40` 크기로 그 점 안에 미리 그려 두고 같은 배율로 함께 키우면, 점이 화면을 채울 때 자연스럽게 다음 세계가 된다.
- 매치 컷: 두 모양이 겹치는 0.1~0.15초 동안만 교차 페이드. 크기·위치·색을 맞추는 게 핵심이고 페이드는 보조다.
- 장면마다 "시작 모양 / 끝 모양"을 표로 먼저 설계하고(위 사슬처럼) 그다음 코드를 쓴다. 이 표를 사용자에게 먼저 보여준다.
- 카메라 속도는 일정하게 유지(가속·감속은 처음과 끝만). 줌인 중 정지 구간을 두지 않는다.
- 깜빡임 주의: 별로 돌진해 하얗게 되는 순간(㉑ 6.3~6.6초)은 밝기가 크게 변한다. 0.3초 이상에 걸쳐 밝아지게 하고 연속으로 반복하지 않는다. 회전 터널도 대비를 낮추고 천천히(봉침 v2 39초 교훈).

**한의원 영상 응용 예시 (사슬 설계 초안)**
- 봉침: 꿀방울 → 벌집 칸 → 정제되는 방울(프리즘 대신 필터) → 주사기 속 꿀빛 → 관절 속으로 들어가는 빛 → 굳은 관절이 풀리는 고리 → 걷는 사람 실루엣 → 다시 꿀방울 → 로고.
- 한약: 약재 한 조각 → 탕기 속 소용돌이 → 한약 파우치 → 몸속으로 퍼지는 따뜻한 빛 → 계절이 바뀌는 원(겨울→봄) → 다시 약재 → 병원 이름.
- 침: 침 끝의 한 점 → 경락 선 → 몸 윤곽 → 다시 한 점.

## 7-6. 글자·도형만으로 공간을 넓혀가는 영상 (레퍼런스 ㉒ — 사용자가 특히 좋아한 기법)
㉒ original_22 (30s, 60fps, 129 BPM, Pankaj Kumar "The frame can't hold it"): 사진·일러스트 없이 **굵은 글자 + 원·삼각형·사각형·띠**만 쓴다. 사용자가 꼽은 장점: ① 한 번도 끊기지 않고 배경을 확대·축소하며 끌고 가는데 어지럽지 않다 ② 글자와 도형이 구부러지며 비트에 맞춰 타격감이 있다 ③ 평평한 배경이 비틀려 입체 공간이 무한히 넓어지는 느낌.

**디자인 체계**: 크림 종이 + 먹색 + 바우하우스 3원색(파랑·빨강·노랑). 글꼴은 아주 굵은 산세리프 1종(Archivo 900, 폭 가변 62~125) + 작은 모노 라벨. 화면 가장자리의 얇은 틀선, 모눈 격자, 모노 라벨("01 / CONTROL", "GRID 14×7", 타임코드)이 **이 영상의 테마 자체**라서 어울린다(봉침 v2에서 HUD가 어색했던 건 테마가 아니었기 때문).

**이야기 구조 = 챕터 라벨**: 01 CONTROL → 02 PRESSURE → 03 ESCAPE → 04 EXPANSION → 05 CHAOS → 06 SILENCE → 07 CONTROL. 틀 안에 갇힌 글자가 점점 커져 틀을 밀고, 탈출하고, 공간이 폭발했다가, 다시 고요한 빈 틀로 돌아온다(수미상관). 구간 길이는 대략 4마디(≈7.4초) 단위.

**① 끊김 없이 확대·축소 — 어지럽지 않은 이유**
| 시각 | 카메라 | 무엇이 일어나나 |
|---|---|---|
| 0~5.5s | 고정 | 빈 틀 → 원 하나 → "F●RM" 글자가 틀을 꽉 채움 → M이 틀 밖으로 밀려남 |
| 5.9~6.3s | **줌아웃 + 기울기** | 그 틀이 사실은 벽에 붙은 종이 카드였음이 드러남(옆에 파란 카드 "MOTION", "04 ·M" 카드) |
| 9.0~9.5s | **줌인** | 빨간 카드 속으로 들어가 "TYPE"이 화면을 채움 |
| 13.1~13.6s | **바닥으로 눕히기** | 평면 모눈이 뒤로 넘어가 끝없는 원근 바닥 + 노란 벽 지평선이 됨 |
| 14~16.7s | **전진 비행** | 바닥에 세워진 거대 글자들(F·R·Y·M·T) 사이를 지나감 |
| 17~18.6s | **글자 속으로 다이브** | "O"의 구멍이 색 고리로 채워지며 출렁 → 그 속으로 빨려 들어가 파란 화면 |
| 27.6~28s | **크게 줌아웃** | 꽉 찬 콜라주 전체가 작은 덩어리로 줄며 회전 → 점 → 처음의 빈 틀 |

어지럽지 않은 규칙:
- **한 번에 한 가지 카메라 움직임**만. 확대·축소·기울이기를 동시에 하지 않는다.
- 각 움직임은 **0.4~0.6초**에 빠르게 끝나고(가속·감속 곡선), 그다음 2~4초는 카메라를 세우고 화면 안의 요소만 움직인다. "빠른 이동 → 머무름"의 리듬.
- 카메라 이동은 **구간이 바뀔 때만**(4마디마다). 박자마다 하지 않는다. 박자는 요소의 타격으로 표현.
- **기준점이 늘 보인다**: 틀선·모눈·지평선 중 하나가 화면에 남아 있어서 "지금 어디쯤인지" 공간감을 잃지 않는다.
- 색이 5개로 고정이라 화면이 바뀌어도 같은 세계로 느껴진다.
- 정지 구간도 일부러 쓴다(측정: 0.2초 이상 정지 18곳, 총 6초). 단 SILENCE·CONTROL처럼 의미 있는 구간이고, 정지 직전에 강한 동작이 있어 "멈춤"이 연출로 읽힌다. **우리 기본 규칙(정지 금지)의 예외는 이런 의도된 쉼표 구간만.**

**② 구부러지는 글자·도형과 타격감**
- 틀이 눌리는 느낌(2~3.4s): 글자가 커질수록 **틀선 오른쪽·아래가 고무처럼 바깥으로 불룩**해지고 박자마다 출렁. 글자는 그대로인데 테두리가 휘어 "압력"이 보인다.
- 글자 폭 가변(가변 글꼴 width 축): 같은 단어가 박자에 맞춰 좁아졌다 넓어졌다. 26~27s "FRAME"은 글자가 기울고 휘며 꿈틀.
- "O"가 말랑한 덩어리처럼 일그러지고, 속 구멍에 파랑·빨강·노랑 고리가 물결치며 채워짐(유체 느낌).
- 콜라주의 도형(노란 원, 파란 원, 검은 삼각형, 빨간 띠, 파란 사각형)이 박자마다 살짝 튀고 기울어짐.
- 타격 타이밍: 움직임 정점이 박자보다 평균 **0.046초 먼저** 온다(측정). 봉침 v3.1에서 정한 "강조는 박자 0.1초 전 출발" 규칙과 같은 원리.

**③ 죽은 배경이 입체 공간으로**
- 평평한 모눈 종이가 0.5초 만에 **뒤로 넘어가 원근 바닥**이 되고, 수평선 너머까지 격자가 이어져 무한 공간이 된다.
- 그 바닥 위에 글자들이 **세워진 입체 물체**처럼 떨어져 서고, 카메라가 그 사이를 지난다.
- 틀(종이)이 벽에 붙은 카드였다는 반전 = 평면이 사물이 되는 순간. 배경 → 물체 → 더 큰 배경.

**우리 파이프라인 구현법**
- 원근 바닥: 모눈 div에 `transform: perspective(1200px) rotateX(0→72deg)`를 0.5초 eInOut. 또는 canvas로 소실점 투영 격자를 직접 그림(더 자유로움). 지평선 위 단색 벽 + 바닥 쪽 살짝 어둡게.
- 화면이 카드가 되는 줌아웃: 장면 전체를 담은 컨테이너에 `scale(1→0.45) rotate(-4deg) perspective rotateY(8deg)` + 주변에 다른 카드들을 미리 배치.
- 글자 속 다이브: 7-5의 포털 줌과 같음(목표점 기준 지수 확대).
- 틀선 휘기: 틀을 SVG path로 그리고 변의 중간 제어점을 박자 펄스 × 압력값만큼 바깥으로 밀기.
- 글자 휘기·폭 변화: 영문은 가변 폭 글꼴(fontsource `@fontsource-variable/archivo` 등)의 `font-variation-settings: 'wdth' N`. 한글은 가변 폭 글꼴이 드물어 글자별 `scaleX` + `skewX`로 대신하고, 크게 휘게 할 땐 SVG `textPath`(곡선 위에 글자 배치)나 `feDisplacementMap` 필터.
- 일그러지는 원: canvas에서 반지름에 `1 + a·sin(kθ + t)` 노이즈를 더한 닫힌 곡선.

**사용자 최애 구간: ㉒ 0~7초** (빈 틀 → 원 → 글자가 틀을 꽉 채움 → 틀 테두리가 압력에 불룩·출렁 → 글자가 밀려 나감 → 틀이 벽의 종이 카드였다는 줌아웃 반전). 새 영상 기획 때 이 연출을 먼저 검토하되, 노래 장르·템포와 맞는지 따져볼 것.

**한의원 영상 응용**: 이야기 구조를 그대로 빌릴 수 있다 — "굳음(CONTROL) → 쑤심(PRESSURE) → 풀림(ESCAPE) → 움직임(EXPANSION) → 편안(SILENCE)". 관절이 틀에 갇힌 글자로, 치료 후 틀이 열리고 공간이 넓어지는 연출. 원내 TV용이라 줌 속도는 레퍼런스보다 1.3배쯤 느리게, 회전은 작게.

## 8. 새 영상 시작 절차
1. 사용자 요청에서 내용·길이·음성/노래 여부 확인 → **테마 한 문장 + 색 3+1 + 글꼴 2 + 움직임 방향**을 먼저 제안.
2. `motion/template/`를 작업 폴더로 복사, `LINES`/`BEATS`/`S`(섹션)/`BGT`를 새 내용으로 교체, 섹션 함수 재작성(헬퍼는 유지).
3. 정지 화면 점검 → 전체 렌더 → QA → 30MB 사본 첨부 + 원본 저장소 푸시.
4. 사용자 피드백은 "몇 초쯤"으로 받는다. 원인을 숫자로 확인(정지 화면, check_motion)한 뒤 쉬운 말로 설명하고 고친다.

## 9. 노래에 맞는 컨셉 잡는 법 (다산한의원 징글 기획 때 조사)
장면을 먼저 짜지 말고 **노래의 구조 → 문법 → 레퍼런스 → 장면표** 순서로 정한다.

**문법 6가지**
1. **에너지 곡선**: 노래가 셀 때 화면도 세고, 쉴 때 쉰다. 구간별(구호/1절/간주/브리지/마지막 구호) 세기를 먼저 적고, 가장 센 연출은 마지막 구호에 아껴 둔다.
2. **박자 3등급**: 모든 박자에 반응하면 유치하다(만화식 "미키마우징").
   - A급(구간 경계) = 카메라 이동·배경 변화
   - B급(가사 핵심 단어) = 글자·도형 타격
   - C급(나머지 박자) = 아주 작은 숨쉬기(틀 4px 출렁, 카메라 ±7px)
3. **반복 + 한 단계씩 더하기**: 구호는 매번 같은 자리·글꼴·동작(화면판 로고송). 대신 회차마다 압력 한 단계만 키운다(예: 채움 → 밀려남 → 입체 → 터짐). 똑같이만 반복하면 지루하다.
4. **소리 = 글자 동시**: 노래가 브랜드 이름을 부르는 순간 화면에서 그 글자가 가장 크다. 징글 각인의 핵심.
5. **장르 결**: 120~150 BPM 경쾌한 팝 = 굵은 글자, 도형 전환, 탄성(스프링) 착지, 밝은 원색. 정돈된 격자 디자인(㉒)도 밝은 색과 스프링을 입히면 팝에 어울린다.
6. **빠르게 움직이고 머문다**: 카메라 이동은 0.5초, 구간 경계에서만. 사이 2~4초는 요소만 박자를 탄다.
